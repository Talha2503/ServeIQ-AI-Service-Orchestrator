# ServeIQ Implementation Plan: Orchestrator & UI Integration

The foundational layer of ServeIQ—the 8 specialized Next.js API agents—is complete and functional. However, the agents currently exist as independent, stateless endpoints. 

This plan proposes the next major phase of development: building an **Orchestrator Layer** to coordinate the agents and a **Dynamic Frontend UI** to allow users to interact with the system seamlessly.

## User Review Required

> [!IMPORTANT]
> **State Management Strategy**
> Currently, the agents are stateless. To chain them together (e.g., Intent -> Discovery -> Ranking), we need to store the intermediate JSON responses. We need to decide:
> 1. Do we want to build a purely client-side orchestrator (where the React frontend holds the state and calls each API sequentially)?
> 2. Or do we want a backend Orchestrator endpoint (`/api/chat`) that uses a database (like Vercel KV, Redis, or Prisma/SQLite) to manage conversational state and coordinate the agents server-side?

## Open Questions

> [!WARNING]
> 1. **UI Design Preference**: Should the user interface be a Chatbot-style interface (like WhatsApp/ChatGPT) or a structured Web App form (like an Uber/Careem clone)?
> 2. **Tailwind Version**: The project uses Tailwind CSS v4 (`@tailwindcss/postcss`). Do you have any specific component libraries (like shadcn/ui) you prefer using?
> 3. **Database Integration**: Should we transition the mock data (`data/providers.json`) into a real database before building the frontend, or continue using the JSON file for the MVP?
